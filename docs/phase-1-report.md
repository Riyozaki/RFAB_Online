# Фаза 1 — промежуточный отчёт (порт на 1.5.97)

Дата: 2026-10-21. Статус: **выполнена первая порция, фаза не завершена**
(остались внутрифункционные патчи и Windows-сборка — см. ниже).

Решения пользователя, принятые как исходные: база
`features-integration@a7d06156`; импорт с историей в этот репозиторий;
область подсчёта игроков для HP/XP — **весь сервер** (Фазы 3–4);
дистрибутив игры — **любой 1.5.97**.

## Что проверено и как

- Аудит ID повторён на импортированном дереве: **278/278** функциональных ID
  и **2806/2806** RTTI ID есть в `version-1-5-97-0.bin` из RFAB
  (`tools/address_db_check.py`, exit 0).
- `skse64_1_5_97.dll` из RFAB статически проанализирована (pefile):
  экспортирует ровно `StartSKSE`; FileVersion хранится как `0.2.0.20`.
  Доказано, что старый код её отвергал (20020 < 20100).
- Раскладки pre-629 сверены из трёх источников: коммиты Tilted `553793fc` /
  `2436384e` (обратная операция), `static_assert` в теге v1.0.0 и версионные
  аксессоры CommonLibSSE-NG для рантаймов `< SSE 1.6.629`
  (ActorValueOwner 0xB0, ActorState 0xB8, CELL runtime data 0x60, размер
  CELL 0x140 — совпали до байта).
- `tools/dump_patch_sites.py`, `tools/address_db_check.py` — синтаксис и
  негативные случаи прогнаны локально.

## Errata к Фазе 0 (честные исправления)

1. В §3.5 анализа написано, что SKSE 2.0.20 «формально проходит» порог 20100.
   **Неверно**: версия хранится как `0.2.0.20`, кумулятив равен 20020 — SKSE
   блокировалась. Исправлено коммитом `2e5295f3`.
2. Патчи `MapMenu.cpp` в Фазе 0 перечислены как живые — они под `#if 0`.
   Живых внутрифункционных патчей 10 групп, не 11 (см. аудит).
3. «Ротации логов не нашёл» — на клиенте ротация есть
   (`TiltedOnlineApp`: rotating sink 5 МБ × 3), у сервера есть настройка
   уровня лога в runner'е. Задача Фазы 1 по логированию сужается до
   единообразия уровней/префиксов сервера.

## Что НЕ проверено (важно)

- **Ни одной сборки клиента и ни одного запуска игры не было.** Весь C++
  выше проверялся чтением и офлайн-скриптами. Первый гейт — Windows-сборка
  (возможны падения `static_assert` размеров, если какая-то вложенная
  структура менялась между 1.6.353 и HEAD не по версионным причинам; ассерты
  для этого и оставлены).
- Внутрифункционные оффсеты (§аудит) всё ещё от 1.6.x — **первый запуск на
  1.5.97 с высокой вероятностью упадёт** на одном из 10 мест, пока не снят
  дамп байтов с вашего exe (`tools/dump_patch_sites.py`, инструкция в
  аудите) и оффсеты не пересчитаны по дизассемблированию.
- Linux-сборка сервера в песочнице не завершена: сеть песочницы режет часть
  хостов xmake-пакетов, актуальный xmake-repo несовместим с xmake 2.9.8
  (пришлось пинить на 2025-05-31 и подсевать пакеты вручную), tiltedcore
  0.2.8 не компилируется GCC 12 без `<mutex>` — это состояние **базового**
  кода в этой среде, серверные исходники в этой фазе не менялись. Проверка
  сборки — Windows-машина или GitHub Actions (`windows.yml`/`linux.yml`)
  после пуша ветки.
- Лаунчерный PE-загрузчик + Steam CEG на вашем конкретном exe 1.5.97 не
  проверялись; для «любого дистрибутива» добавлен только fallback версии.
  Если exe упакован нестандартно, загрузчик — первый кандидат на отказ,
  диагностируется по логам лаунчера.

## Риски и следующие шаги (по порядку)

1. **Windows-сборка** по `BUILD.md` → прислать ошибки компиляции/ассерты.
2. **Дамп патч-сайтов** с вашего `SkyrimSE.exe` → пересчитаю 10 оффсетов,
   внесу отдельным коммитом с таблицей инструкций.
3. Первый запуск: одиночный клиент + локальный сервер, чек-лист:
   запуск до меню → загрузка базы 1.5.97 в логе → SKSE «is active» →
   новая игра → подключение к серверу → второй клиент видит первого.
   При краше: краш-лог NetScriptFramework + `tp_client.log`.
4. Дальше по плану Фазы 1: аудит остальных структур (85 sizeof) против
   CommonLibSSE-NG SE-аксессоров — таблицей расхождений; затем Фазы 2–5.
   Напоминаю зафиксированное решение: N для HP и область XP — **все игроки
   сервера** (в конфиге оставлю переключаемость, дефолт — сервер).
