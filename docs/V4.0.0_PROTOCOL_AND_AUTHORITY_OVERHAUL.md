# RFAB Online `v4.0.0` — Protocol & Authority Architecture Overhaul

## 1. Version & Wire-Compatibility Boundary (`v4.0.0`)
- **`VERSION` (`4.0.0`)** is the single source of truth for:
  - `Code/common/RfabModpackCompat.h` (`kRfabOnlineVersion = "4.0.0"`), enforced at build/CI time by `Tools/rfab/check_release_invariants.py`.
  - `Code/common/xmake.lua` + `Code/common/BuildInfo.h.in`: `BUILD_COMMIT` resolves to `"v4.0.0"` on exact tag `v4.0.0` and `"v4.0.0-g<short_sha>"` on branch builds, so `RfabCompat::AreBuildVersionsProtocolCompatible` accepts same-major `v4.0.x` peers while deterministically rejecting `v3.1.x` peers across the `v4.0.0` wire change.

## 2. Wire Protocol Changes (`Code/encoding`)
- **`uint32_t HealthRevision{0}`** added (`SerializeRaw` / `DeserializeRaw` / `operator==`) to:
  1. `AssignCharacterResponse`
  2. `CharacterSpawnRequest`
  3. `NotifySpawnData`
  4. `NotifyOwnershipTransfer`
  5. `NotifyDeathStateChange`
- **`GameId BaseId{}`** added to `Structs/ActorData` so placed `TESLevCharacter` static template resolution travels end-to-end across `AssignCharacterRequest`, `RequestOwnershipClaim`, and `NotifySpawnData`.

## 3. Authority Lease & Decline-Cascade Model (`Code/common/Authority/Lease.{h,cpp}`)
- `WorldNpcLeasePolicy()` sets an `8000 ms` lease window for world NPCs while preserving infinite leases (`LeaseDurationMs = 0`) for player avatars, player summons, and mounts.
- `RefreshUnrevoked()` extends an uncontested owner's expired world-NPC lease without churning `Epoch` when resuming from a solo pause menu.
- `Authority::Claim` checks `!acChallenger.InRange` **before** `!ownerStillSimulating`, preventing out-of-range peers from claiming unowned or expired entities while still allowing an in-range downed peer to adopt an unowned entity.
- `Authority::DeclineList` (`kDefaultDeclineTtlMs = 15000 ms`) replaces the raw `InvalidOwners` set on `OwnerComponent` and is intentionally preserved across `OwnerComponent::Apply`, eliminating `P1 <-> P2` ownership ping-pong in 3+ player parties when cells stream in at different speeds.

## 4. Server & Client Runtime Invariants
- **Monotonic `HealthRevision` & Owner Revision Acks:** Every spawned character initializes `ActorValuesComponent::HealthRevision >= 1`. Whenever an owner-originated write (`RequestHealthChangeBroadcast`, `RequestActorValueChanges`, `RequestDeathStateChange`, `RequestOwnershipClaim`) advances `HealthRevision` without echoing `NotifySpawnData` to the owner, the server sends a lightweight `NotifyActorValueChanges{Id, HealthRevision}` with empty `Values` to the owner so subsequent Requiem/RFAB health regeneration is never misclassified as `kStaleIncrease`.
- **Unpaused Simulation Keepalive & Co-op Menu Handoff:** `CharacterService::RunLocalUpdates()` emits an empty 5-byte `ClientReferencesMoveRequest` every `2000 ms` when unpaused (`UpdatePausedPump` never calls `RunLocalUpdates`). `SweepExpiredWorldNpcLeases()` hands off an expired world-NPC lease only when another peer in range has simulated within `4000 ms`, keeping solo `StatsMenu` browsing churn-free while handing off active co-op fights in ~8 seconds.
- **Pure Server-Granted Voluntary Claims & Component-Swap Safety:** `RequestVoluntaryOwnershipClaim()` sends `RequestOwnershipClaim` (1500 ms per-entity throttle) without pre-emplacing `LocalComponent` or mutating `m_ownershipLeases`. `OnNotifyRelinquishControl` and `OnNotifyMount` emplace `RemoteComponent` **before** removing `LocalComponent` so `EntityIndexTable::FindByServerId` never sees a transient unbound window.
