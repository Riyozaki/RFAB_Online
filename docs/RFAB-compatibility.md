# Матрица совместимости с RFAB

Документ отвечает на один вопрос: **что из сборки RFAB трогает этот форк, что
с этим делать и что проверено.**

Колонка «статус»:

* **проверено кодом** — сверено с исходниками/данными сборки и с историей
  upstream (pre-AE эталон 1.5.97), ошибок не найдено;
* **требует проверки в игре** — реализовано, но подтвердить можно только
  запуском игры (в среде разработки нет Windows-сборки).

## 1. Версии

| Компонент | Требование | Примечание |
| --- | --- | --- |
| Skyrim SE | **1.5.97.0.8** | AE 1.6.x не поддерживается: раскладки структур и адреса другие. |
| SKSE64 | 2.0.20 (`skse64_1_5_97.dll`) | Другая версия = другой билд exe, плагин не загрузится. |
| Address Library | SE-вариант (`version-1-5-97-0.bin`) | AE-база (`versionlib-1-6-x`) не подходит. |
| RFAB | сборка SE XI Prime (как в `MO2/mods/RFAB`) | Нужны как минимум `RFAB.esp` и `RFAB_XP_Handler.pex`. |
| Мод-лист | идентичный у всех игроков | Иначе разъедутся FormID-ы (`GameId`). |
| Клиент/сервер | **один и тот же коммит** | Проверяется по `BUILD_COMMIT` при аутентификации. |
| Протокол | v3 | Логируется с обеих сторон; v3 добавил `RfabXpTotal` в аутентификацию. |

## 2. Системы RFAB и их взаимодействие с форком

| Система RFAB | Что делает сборка | Что делает форк | Статус |
| --- | --- | --- | --- |
| Опыт (`RFAB_XP_Handler`) | `ModXP(int)` = `PlayerXP.Mod(aiXP)` + `Game.SetPlayerExperience(+aiXP)`; множитель — `CalculateXP` через `MultiplierXP` | Клиент замечает рост `PlayerXP`, отправляет дельту; сервер раздаёт её всем (кроме автора); получатель воспроизводит тело `ModXP` + проверку порога уровня | требует проверки в игре (`docs/rfab-xp.md`) |
| Таблицы опыта (`Experience.ini`, `RaceList.json`, `BossList.json`, `Quests.ini`) | Считают базовый XP за убийство/книгу/квест | Не трогаются: сервер передаёт *готовую* сумму, посчитанную RFAB у инициатора | проверено кодом |
| Здоровье врагов | RFAB меняет статы через перки/записи; в рантайме HP — обычный актор-велью | Сервер умножает **базовый** максимум на `N+1` и присылает клиентам; база запоминается по форме, а не по сущности | требует проверки в игре |
| Уровень игрока / `SetPlayerLevel` в `OnInit` | `RFAB_XP_Handler.OnInit` пересчитывает порог 1-го уровня | Не вмешивается; важно, чтобы все клиенты имели одинаковую `Experience.ini` | проверено кодом |
| Уведомления (UIlib/JSONUtil) | Всплывающие сообщения об XP | Не дублируются: на чужой опыт показывается только HUD-строка `Level up` при пересечении порога | требует проверки в игре |
| Уведомления о новом уровне (`ShowLevelUp`) | Flash-анимация полосы | Не воспроизводится нативной стороной; ванильный уровень растёт штатно | известно ограничение |
| Счётчик фалмеров (`RFAB_Counter_FalmersKilled`) | Глобал-счётчик | Не синхронизируется (это локальная статистика квестов RFAB) | известно ограничение |
| Реестр прогресса | Опыт живёт в сейве клиента | Сервер помнит максимум опыта на ник и при входе досылает разницу (краш, старый сейв, новый персонаж) | требует проверки в игре (`docs/configuration.md`) |
| Книги/квесты RFAB | Начисляют XP локально у каждого клиента | Дедуп: серверное окно 5 с по одинаковой сумме + клиентский `EchoFilter` 1.5 с (не начислять то, что уже начислено локально) | требует проверки в игре |

## 3. Что форк **не** делает с RFAB (и почему)

* **Не патчит `.esp`/`.pex` RFAB.** Любая правка сборки ломает её целостность
  и мод-чек; всё делается через рантайм.
* **Не вызывает `ModXP` напрямую.** Это Papyrus-**функция** скрипта на квесте;
  нативный вызов требует сборки `BSScript`-стека, пути для которого в кодовой
  базе нет, а ошибка раскладки стека = CTD. Вместо этого воспроизводятся ровно
  те две записи, которые делает `ModXP` (см. `docs/rfab-xp.md`). Если RFAB
  изменит тело `ModXP`, нужно поправить `Code/client/Services/RfabXp.cpp`.
* **Не трогает `MultiplierXP`.** Множитель RFAB остаётся тем, что в
  `RFAB_XP_Settings.json`; он должен быть одинаковым у всех игроков.
* **Не синхронизирует квесты RFAB.** Квесты — отдельная (нереализованная в STR
  для SSE) подсистема; в мультиплеере у каждого игрока свой квест-лог.

## 4. Известные конфликты и риски

| Риск | Проявление | Смягчение |
| --- | --- | --- |
| Двойной опыт на квестах | квест завершается у всех клиентов, каждый начисляет локально и сообщает | серверное окно одинаковых сумм + клиентский `EchoFilter`; при ложных срабатываниях `uXpShareDedupWindowMs = 0` |
| HP-скейлинг против скриптовых порогов боссов | босс с фазой «на 50 % HP» ведёт себя иначе при ×4 | доля HP сохраняется при пересчёте; суммоны не скейлятся; при проблемах `bEnableHealthScaling = false` |
| RFAB-перки, меняющие `max health` динамически | сервер видит новый максимум от владельца и считает его базой | база берётся один раз на форму; при смене множителя пересчёт идёт от неё |
| Разные версии RFAB у игроков | разные FormID/суммы XP | мод-чек (`ModPolicy:*`) + «один коммит клиента и сервера» |
| Загрузка одиночного сейва в сессии | рассинхрон, вылет | `[Save] bStopSessionOnLoad = 1` — соединение закрывается |
| Сейв, сделанный в сессии | содержит состояние общего мира | помечается в `RFABOnline_saves_index.jsonl` |

## 5. Что проверить в игре в первую очередь

Полный чек-лист — `docs/manual-test-checklist.md`. Минимум:

1. 1 игрок: HP врагов и опыт **не отличаются** от обычной игры RFAB.
2. 2 игрока: HP врага ×3, опыт за убийство одинаковый у обоих.
3. 3 игрока: ×4, опыт за квест начислен один раз каждому.
4. Выход владельца ячейки в бою: враг не «замерзает», HP не скачет.
5. Смена ячейки и возврат: HP врагов остаются ×N (нет ×N²).
