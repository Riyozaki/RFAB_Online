# Трансляция Address Library ID: AE (1.6.x) → SE (1.5.97)

Документ описывает, как закрывались ID, которые клиент запрашивает у Address
Library, что подтверждено независимыми источниками и что осталось на разбор с
исполняемым файлом игры.

Связанные файлы:

| Файл | Что это |
|---|---|
| `Code/common/address_library/SkyrimIdMap1597.inl` | генерируемая таблица `{ae_id, se_id}` |
| `docs/phase1/address_id_inventory.csv` | все ID клиента: источник, тип, первая ссылка |
| `docs/phase1/id_worklist.csv` | незакрытые ID + соседние известные пары |
| `docs/phase1/id_candidates.csv` | интервалы-кандидаты для незакрытых ID |
| `docs/phase1/id_pairs_curated.csv` | пары, восстановленные вручную/из истории |
| `docs/phase1/id_pairs_derived.csv` | вывод `history_pairs.py` (отчёт, не вход) |

## 1. Итог

```
всего ID в клиенте   3083
закрыто              2989  (97.0%)
  CommonLibSSE-NG    2891
  история 1.5.97       17  (curated)
  эвристика фазы 0     81
не закрыто             94  (79 указателей, 13 VersionDbPtr, 2 RTTI)
```

Было 105 незакрытых. Закрыто 17 (11 в этой итерации, 6 — после перехода с
сопоставления по имени переменной на сопоставление по **типу указателя**).
Пять ID, которые фаза 0 «закрывала» заведомо неверно (два разных AE ID на один
SE ID), были сняты из таблицы и затем закрыты корректно — «карантин» пуст.

## 2. Откуда берутся пары

### 2.1. CommonLibSSE-NG — 2891 пара

`RELOCATION_ID(se, ae)` / `REL::VariantID` из `include/RE/**`. Пары точные, но
покрывают только то, что объявлено в NG. Выгрузка и проверка —
`tools/port1597/extract_clibng_pairs.py` и `verify_pairs.py`.

### 2.2. Эвристика фазы 0 — 81 пара

Сопоставление по имени переменной с деревом 2021 года. Используется только там,
где NG молчит, и только при единственном кандидате. Две пары фазы 0 были
опровергнуты (см. § 4.2).

### 2.3. История форка — 17 пар (новое)

В истории `TiltedEvolution` есть два коммита, которые вместе дают точный ответ:

| Коммит | Что делает |
|---|---|
| `03c16aa9` (2021-11-01) | последнее дерево, которое ещё целится в **1.5.97**: `POINTER_SKYRIMSE(T, name, 0x14063B060 - 0x140000000)` |
| `6b2afebc` (2022-02-12) | «Use address library instead of hardcoded addresses»: те же строки, но с ID `POINTER_SKYRIMSE(T, name, 38952)` |

Удалённые в `6b2afebc` адреса — **AE** (после перехода на 1.6.x), поэтому
напрямую они бесполезны. Но в дереве `03c16aa9` те же символы объявлены
адресами **1.5.97**, а база 1.5.97 (`version-1-5-97-0.bin`) — это полная таблица
`id → смещение`. Обратный поиск даёт SE ID.

Проверка, что дерево `03c16aa9` действительно 1.5.97 (а не 1.6.x):

| Дерево | Сырых адресов | Из них есть в базе 1.5.97 |
|---|---|---|
| `03c16aa9` (2021-11-01) | 101 | **100 (99.0%)** |
| `77b85e91` (2021-12-15) | 134 | 9 (6.7%) |
| `bd3c7621` (2022-01-15) | 134 | 9 (6.7%) |
| `9e62ad03` (2022-02-10) | 143 | 11 (7.7%) |

То есть переход на AE произошёл между 1 ноября и 15 декабря 2021 года, и
адреса из более поздних деревьев для порта непригодны.

Сопоставление делается по **типу указателя** (`TEquip`, `TUnEquipShout`,
`PlayerCharacter*`), а не по имени переменной: одно имя (`s_equipFunc`)
используется для четырёх разных функций. Имя переменной — только запасной ключ.
Пара принимается, если все вхождения типа дают один и тот же SE ID; иначе
кандидаты попадают в `id_candidates.csv` как «ambiguous».

## 3. Чем это подтверждено

### 3.1. Независимая сверка пар

`tools/port1597/verify_pairs.py` берёт два независимых источника — имена и
адреса 1.5.97 из дерева 2021 года и пары `(SE, AE)` из NG — и проверяет, что
база 1.5.97 отображает SE ID ровно в тот адрес, который использовал старый код:

```
database entries: 778674
legacy named addresses: 2807
named id pairs: 7967
checked: 2805  matched: 2805  mismatched: 0
```

Ноль расхождений одновременно доказывает корректность разбора формата 1
(включая бит масштабирования смещений на размер указателя) и корректность
выгруженных пар.

### 3.2. Самотест

```
g++ -std=c++20 -I Code/common tools/port1597/selftest.cpp \
    Code/common/address_library/*.cpp -o /tmp/selftest
/tmp/selftest --database ~/.ref/rfab/al-1-5-97.bin
-> 82 checks, 0 failures
```

Проверяется в том числе: таблица строго отсортирована, все 2989 переведённых ID
присутствуют в базе 1.5.97 (missing 0), у незакрытых ID нет выдуманных значений.

### 3.3. Регрессия генератора

`python3 tools/port1597/gen_inl.py --check` — падает, если `.inl` или
`address_id_inventory.csv` устарели относительно исходников.

## 4. Найденные проблемы

### 4.1. Одно имя — две функции

`POINTER_SKYRIMSE(TAnimationStep, PerformIdleAction, 38952)` и
`POINTER_SKYRIMSE(Tsub_14063CFB0, sub_14063CFB0, 38952)` — один и тот же AE
адрес под двумя именами. Имя `sub_14063CFB0` устарело: в 1.5.97 это **другая**
функция (`0x63CFB0` → SE ID 38047), а PerformIdleAction — `0x63B060` → 37998.
В AE оба имени получили адрес `0x661070`, то есть в AE `RePerformIdleAction`
вызывает PerformIdleAction. Для порта взято 37998 (поведение AE), а не 38047.

Аналогично `s_pickUpObject` объявлен дважды — в `Actor.cpp:1380` (AE 37521) и
`PlayerCharacter.cpp:248` (AE 40533) — это разные функции с разными адресами
(`0x5E6580` и `0x6A5300`). Сопоставление сделано по файлам.

### 4.2. Пары фазы 0, которые были неверны

Фаза 0 сопоставляла по имени переменной, поэтому две разные функции с одним
именем получали один SE ID:

| AE | SE (было) | Что не так |
|---:|---:|---|
| 35993, 36035 | оба 35145 | на самом деле 35100 и 35145 |
| 38896, 38929 | оба 37940 | на самом деле 37940 и 37974 |
| 38903, 38934 | оба 37947 | на самом деле 37947 и 37979 |

Такие пары теперь отбрасываются механизмом `QUARANTINE` в `gen_inl.py`
(сейчас список пуст, потому что все шесть ID закрыты по-настоящему).

### 4.3. Монотонность пар соблюдается не всегда

В районе `11600` пары из NG дают `11600 → 11483`, но `11617 → 11471`, то есть
порядок функций между версиями изменился. Вывод: интервальный метод
(`id_candidates.py`) — эвристика для сужения поиска, а не доказательство.

### 4.4. RTTI-диапазон

RTTI-записи (`392578`, `400180`) лежат в отдельном блоке ID. Пары NG там есть
(например `400508 → 514355`), и порядок в целом монотонный, но у `400180`
соседние пары дают пустой интервал — значит в этом месте совпадение порядка
нарушено. Для RTTI интервальный метод нельзя считать надёжным.

## 5. Что осталось: 94 ID

Все 94 имеют имя символа и точку использования (`id_worklist.csv`), но ни NG,
ни история форка их не покрывают: код появился **после** перехода на AE, поэтому
адресов 1.5.97 для этих функций не существует ни в одном доступном источнике.

| ID | Файл | Комментарий |

| 38899 | `s_unequipAll` | 37942, 37943, 37944 |

неверный RTTI ID — это тихий сбой приведения типов. Внести после проверки.

### 5.2. Как закрывать остаток (нужен exe)

1. Открыть `SkyrimSE.exe` 1.5.97 в IDA/Ghidra с базой `0x140000000`.
2. Для каждого ID из `id_worklist.csv` взять символ и точку вызова, найти
   функцию по перекрёстным ссылкам от известных соседей (столбцы
   `prev_mapped_se` / `next_mapped_se` — это уже проверенные адреса).
3. Получить RVA, найти его в базе 1.5.97 (`tools/port1597` умеет: обратный
   поиск по смещению), либо сразу взять ID.
4. Добавить строку в `docs/phase1/id_pairs_curated.csv` с полем `evidence`
   (адрес + откуда взято) и выполнить:

```bash
python3 tools/port1597/gen_inl.py            # перегенерировать таблицу
python3 tools/port1597/history_pairs.py ... --check
python3 tools/port1597/id_worklist.py
```

5. Проверить в игре: `TP_ALLOW_UNRESOLVED_ADDRESS_IDS` не задавать — клиент сам
   откажется стартовать, пока хоть один ID не закрыт, и покажет список.

## 6. Что НЕ проверено

* Ни одна из 2989 пар не проверена **в игре**: проверки только статические
  (сверка с двумя независимыми источниками и с базой 1.5.97).
* 17 пар `curated` опираются на соответствие «тип указателя → адрес»;
  для 2 из них (`CtorT`) дополнительно использован порядок объявлений.
* `38952 → 37998` — единственная пара, где поведение AE отличается от 1.5.97;
  если `RePerformIdleAction` начнёт вести себя не так, как ожидается, начинать
  разбор нужно с неё.
* Девять `VersionDbPtr` в остатке относятся к версионированным структурам
  (`BSRandom`, `TESObjectCELL`), их ID также требуют exe.
