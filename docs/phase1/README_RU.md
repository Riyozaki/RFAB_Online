# Фаза 1. Порт на Skyrim SE 1.5.97 — статус

Документ фиксирует, что уже сделано в фазе 1, чем это подтверждено и что
осталось. Разделы «Проверено» и «Не проверено» — принципиальные: без доступа к
Windows + Skyrim 1.5.97 любое поведение в игре считается неподтверждённым.

## 1. Что сделано в этой итерации

### 1.1. Слой Address Library (Ф1.2, часть)

Было: клиент умел читать **только формат 2** и **только файл**
`versionlib-<версия>.bin`; при любой другой базе — диалог «All in one (1.6.X)»
и `exit(4)`.

Стало:

| Возможность | Файл |
|---|---|
| Форматы баз **1, 2, 5** | `Code/common/address_library/AddressLibrary.{h,cpp}` |
| Имена `versionlib-1-5-97-0.bin` **и** `version-1-5-97-0.bin` | там же, `GetCandidateFileNames` |
| Строгая проверка заголовка, границ, усечения, переполнений | там же |
| Проверка «все смещения внутри образа игры» | `VersionDb::CheckImageBounds` |
| Отказ, если содержимое базы не совпадает с версией игры | `VersionDb::Load` |
| Явное сообщение с причиной отказа (файл, версия, формат) | `Code/client/main.cpp` |

Слой вынесен в `Code/common` (портативный, без `Windows.h`), поэтому он
компилируется и тестируется на Linux — это единственная часть клиента, которую
можно проверить в этой среде.

### 1.2. Трансляция ID AE → 1.5.97 (Ф1.2, ключевая часть)

Код клиента написан на ID 1.6.x. ID в Address Library **не переносимы между
версиями**, поэтому на 1.5.97 каждый ID нужно переводить. Реализовано:

* таблица соответствий `Code/common/address_library/SkyrimIdMap1597.inl`
  (генерируется, 3083 записи);
* трансляция в `VersionDb::ResolveId` — прозрачно для всех
  `POINTER_SKYRIMSE` и `VersionDbPtr`;
* **аудит при старте**: перебираются все ID, которые использует код, и клиент
  отказывается запускаться, если хоть один не разрешён (со списком в диалоге и
  в логе). Обход — только через `TP_ALLOW_UNRESOLVED_ADDRESS_IDS=1`.

Источники соответствий (в порядке приоритета):

| Источник | Записей | Комментарий |
|---|---|---|
| История форка: дерево 1.5.97 + база адресов | 17 | точные адреса 1.5.97 из дерева до миграции на AE, `docs/phase1/id_pairs_curated.csv` |
| CommonLibSSE-NG (`RELOCATION_ID`, `REL::VariantID`) | 17 470 пар | точные пары SE/AE, выгружены в `docs/phase1/clibng_id_pairs.csv` |
| Фаза 0, эвристика по дереву 2021 года | 81 | используется, только если NG не покрывает ID |

Результат по 3083 ID, которые реально встречаются в коде клиента:

```
всего            3083
закрыто          2989   (97.0%)
  из CommonLibSSE-NG    2891
  из истории 1.5.97       17
  из карты фазы 0         81
не закрыто         94   (79 указателей, 13 VersionDbPtr, 2 RTTI)
```

Подробности методики, найденные при этом ошибки и порядок закрытия остатка —
`docs/phase1/IDS_RU.md`.

Это радикально лучше оценки фазы 0 (там «вручную» числилось 139 ID только по
указателям): выяснилось, что NG содержит готовые пары, в том числе для RTTI
(2806 ID в `RTTI.cpp`), которые в фазе 0 вообще не учитывались.

## 2. Чем это подтверждено

### 2.1. Независимая сверка пар (`tools/port1597/verify_pairs.py`)

Берутся два независимых источника:

* дерево TiltedEvolution от ноября 2021 года (до миграции на AE) — в нём
  **сырые адреса 1.5.97**, по именам (`RTTI_TESForm(0x1E10E30)`);
* пары `(SE id, AE id)` из CommonLibSSE-NG.

Если парсер базы и пары корректны, база 1.5.97 обязана отобразить SE-идентификатор
ровно в тот адрес, который использовал старый код.

```
database entries: 778674
legacy named addresses: 2807
named id pairs: 7967
checked: 2805  matched: 2805  mismatched: 0
```

Это одновременно доказывает корректность разбора формата 1 (включая бит
масштабирования смещений на размер указателя) и корректность выгруженных пар.

### 2.2. Самотест без зависимостей (`tools/port1597/selftest.cpp`)

```
79 checks, 0 failures
```

Покрыто: разбор версий, форматы 1/2/5, бит масштабирования, отказ на
неподдерживаемом формате/усечении/пустом файле, сортировка таблицы, спорные ID,
аудит, разбор реальной базы 1.5.97 (778 674 записи, формат 1, максимум смещений
`0x35f3830` = внутри образа) и проверка, что **все 2978 переведённых ID
присутствуют в базе**.

### 2.3. Юнит-тесты репозитория

`Code/tests/address_library.cpp` (catch2) — тот же набор в рамках штатного
`TPTests`. Заодно починен сам таргет тестов: в `add_requires` не был объявлен
`catch2`, а `TPTests` не зависел от `CommonLib`.

## 3. Что осталось в фазе 1

| # | Задача | Объём | Заметки |
|---|---|---|---|
| 1.3 | Развернуть оставшиеся **94 ID** | 1–2 дня с exe | офлайн-источники исчерпаны (см. `docs/phase1/IDS_RU.md`); без exe 1.5.97 остаток не закрывается — нужен IDA/Ghidra |
| 1.4 | **Раскладки структур** под 1.5.97 | 3–5 дней | уточнено: раскладка меняется не в AE, а в 1.6.629, отличий всего 16 полей в 8 классах — см. `docs/phase1/LAYOUTS_RU.md`. Базовая цепочка (`ExtraDataList` → `TESObjectREFR` → `Actor` → `PlayerCharacter`) и `BSAnimationGraphManager` уже переведены на профили; `CombatController` открыт |
| 1.5 | Хуки и сигнатуры (`TP_HOOK`, 90 шт.) | 5–10 дней | часть хуков ставится на функции, которых в 1.5.97 нет или они другой длины — потребуется отдельная последовательность патча |
| 1.6 | Сквозная проверка в игре | — | только на Windows + 1.5.97 + RFAB |

Порядок: 1.3 → 1.4 → 1.5. Пункт 1.4 нельзя начинать без 1.3, потому что
незакрытый ID означает неизвестный адрес функции, а значит и неизвестную
структуру, которую она принимает.

Отдельный результат этой итерации — ревизия оценки 1.4. Разница раскладок
1.5.97 и 1.6.1170 оказалась не «всё сдвинуто на +8», а 16 конкретных полей в
8 классах, причём источник и граница сдвига (1.6.629) подтверждаются NG.
Подробности и порядок правок: `docs/phase1/LAYOUTS_RU.md`.

## 4. Ручной чеклист (то, что нельзя проверить здесь)

Проверять на чистой 1.5.97 + SKSE 2.0.20 + Address Library 1.5.97, затем на RFAB.

1. Запуск: клиент стартует, в `logs/tp_client.log` есть строка
   `SkyrimSE 1.5.97.0 detected: ... translating N of 3083 AE ids`.
2. Аудит: `Address id audit: 2989/3083 resolved` и отсутствие диалога об
   неполном порте (после закрытия 1.3 — `3083/3083`).
3. Подключение к серверу, спавн в мир, движение — базовые `POINTER_SKYRIMSE`
   (игрок, камера, ввод) работают.
4. Меню/UI: `UI.cpp`, `MapMenu`, `SkillsMenu`, `Favorites` — RTTI и хуки.
5. Инвентарь/экипировка: `EquipManager` (ID 38894/38897/38901 уже
   перекрыты; 38929/38934 восстановлены из истории, см. `IDS_RU.md`).
6. Отключение и повторное подключение.
7. RFAB: запуск через MO2, проверка, что SKSE-плагины RFAB не конфликтуют.

## 5. Известные расхождения и риски

* **Разобрано: расхождения фазы 0.** Из четырёх расхождений (38894, 38897,
  38901, 69192) три оказались ошибкой эвристики: она отображала 38894 и 38897 в
  один ID 37940. Приняты значения NG; две пары фазы 0 (35993/36035 и
  38903/38934) были опровергнуты и заменены на восстановленные из истории — см.
  `IDS_RU.md`, § 4.2. Непроверенным в игре остаётся только 69192 (NG vs фаза 0:
  67847 vs 67822), принят вариант NG.
* **Не проверено:** ни один запуск в игре; сборка клиента (нужен MSVC);
  поведение формата 5 (в 1.5.97 используется формат 1, формат 5 поддержан
  «на будущее» для 1.7.x).
* **Ограничение аудита:** он видит только ID, встречающиеся в исходниках
  литералами. Если ID когда-нибудь начнут вычислять в рантайме, аудит их
  пропустит.
* **Лицензии:** `clibng_id_pairs.csv` — таблица числовых ID, полученная из
  CommonLibSSE-NG (GPL-3.0). Код NG не копировался; данные используются как
  справочные. При публикации форка стоит указать источник.
