# Раскладки структур: 1.5.97 против 1.6.x

Документ отвечает на вопрос «насколько сильно структуры игры отличаются между
1.5.97 и 1.6.x» и задаёт план правок. Вывод неожиданно утешительный.

## 1. Главное: раскладки поменялись не в AE, а в 1.6.629

В фазе 0 разница была описана как «AE сдвинул поля на +8». Это неточно.
Проверка по CommonLibSSE-NG (`include/RE/**`) даёт точную границу:

```
STATIC_ASSERT_SIZE(TESObjectREFR, 0x98, 0xA0, 0x98);   // SE, AE(post-629), VR
STATIC_ASSERT_SIZE(ExtraDataList, 0x18, 0x20, 0x18);
STATIC_ASSERT_SIZE(Actor,         0x2B0, 0x2B8, 0x2B0, 0xC0);
RUNTIME_DATA_ACCESSOR_VERSIONED(..., SKSE::RUNTIME_SSE_1_6_629, 0x88, 0x90);
```

То есть:

* **1.5.97 (SE) == 1.6.318/1.6.353** по раскладке — сдвига ещё нет;
* сдвиг на `+0x8` появился в **1.6.629** и унаследован всеми более новыми AE;
* NG описывает обе раскладки и выбирает нужную в рантайме по версии модуля.

Форк `TiltedEvolution-rwf` написан под 1.6.1170, поэтому его `static_assert`
фиксируют «новую» (post-629) раскладку. Дерево 2021 года фиксирует «старую» —
она же раскладка 1.5.97.

## 2. Полный список отличающихся полей

NG содержит ровно 16 «версионированных» обращений к членам, у которых смещения
SE и AE различаются. Других отличий в публичном API NG нет:

| Класс | Поле/блок | SE (1.5.97) | 1.6.629+ | Примечание |
|---|---|---|---|---|
| `Actor` | `MagicTarget` (каст) | 0x98 | 0xA0 | следствие роста `ExtraDataList` |
| `Actor` | `ActorValueOwner` | 0xB0 | 0xB8 | |
| `Actor` | `ActorState` | 0xB8 | 0xC0 | |
| `Actor` | sink `BSTransformDeltaEvent` | 0xC8 | 0xD0 | |
| `Actor` | sink `bhkCharacterMoveFinishEvent` | 0xD0 | 0xD8 | |
| `Actor` | `IPostAnimationChannelUpdateFunctor` | 0xD8 | 0xE0 | |
| `Actor` | runtime data (`GetActorRuntimeData`) | 0xE0 | 0xE8 | в форке это `flags1` |
| `PlayerCharacter` | runtime data ×4 | 0x2B0/0x2B8/0x2C0/0x2C8 | +0x8 каждый | следствие роста `Actor` |
| `TESObjectREFR` | `REFERENCE_RUNTIME_DATA` | 0x88 | 0x90 | `ExtraDataList` 0x18 → 0x20 |
| `BSAnimationGraphManager` | runtime data | 0x98 | 0xA0 | самостоятельный сдвиг |
| `CombatController` | runtime data | 0x68 | 0x70 | самостоятельный сдвиг |
| `Inventory3DManager` | runtime data | 0x58 | 0x60 | самостоятельный сдвиг |
| `TESObjectCELL` | runtime data | 0x60 | 0x68 | самостоятельный сдвиг |

Отдельно, уже за пределами 1.6.629 (для нас не важно, но пусть будет в
документе): `BGSSaveLoadManager` 0x2b0 → 0x2f8 (1.6.1130) и
`AttackBlockHandler` 0x18 → 0x58 (1.7.99).

### Цепочка размеров

```
ExtraDataList   0x18 (SE)     0x20 (AE 629+)
TESObjectREFR   0x98          0xA0
Actor           0x2B0         0x2B8
PlayerCharacter +8 ко всем полям после базового класса
```

Если привести `ExtraDataList` к 0x18, то `TESObjectREFR`, `Actor` и
`PlayerCharacter` «съезжают» на 8 байт вниз автоматически — правки в них
сводятся к переносу `static_assert`.

## 3. Сверка с деревом 2021 года

`tools/port1597/compare_layouts.py` сопоставляет утверждения двух деревьев:

```
offset assertions: current 143, legacy 155, common 113
sizeof assertions: current  76, legacy  46, common 37

дельта смещений:  +0x0 — 80, +0x8 — 12, остальное — правки/переименования форка
дельта размеров:  +0x0 — 27
```

Все 12 «+0x8» — это ровно поля `Actor` из таблицы выше. Отрицательные дельты
(`Actor::magicItems -0x220`, `PlayerCharacter::objectives -0x250` и т. п.) —
не версия игры, а переписанные вручную заглушки форка; их нельзя использовать
как источник истины.

## 4. Стратегия

Рассматривались три варианта.

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Одна сборка, рантайм-ветки на каждое смещение (как NG) | один бинарник на обе версии | переписать все обращения к полям, риск ошибки в каждой ветке; форк использует прямые обращения `pActor->flags1` |
| B. Две сборки, раскладка выбирается на этапе компиляции | ноль риска для 1.6.x, минимум изменений в коде | две конфигурации сборки и тестирования |
| C. Только 1.5.97, 1.6.x выбросить | проще всего | ломает совместимость с апстримом |

**Выбран B.** Причины:

1. Изменений мало (таблица выше) — переписывать каждое обращение к полю ради
   16 смещений нерационально;
2. сборка 1.6.x остаётся байт-в-байт прежней, то есть требование «не ломать
   существующее» выполняется буквально;
3. RFAB — это 1.5.97, поэтому основным становится профиль `1597`, а `1600`
   остаётся для сверки с апстримом и для отладки регрессий.

Реализация:

* `xmake f --skyrim_profile=1597|1600` (по умолчанию `1600`) → define
  `TP_GAME_PROFILE_1597`;
* в заголовках структур — `TP_LAYOUT(se, ae)` в `static_assert`, чтобы
  компилятор проверял обе раскладки;
* там, где поле физически отсутствует/добавлено, — `#if TP_PROFILE_IS_1597`.

## 5. Порядок правок (задача 1.4)

| Шаг | Что | Проверка |
|---|---|---|
| 1 | `ExtraDataList` → 0x18 для 1597 (`Bitfield`/`lock` по NG) | `static_assert(sizeof(ExtraDataList) == TP_LAYOUT(0x18, 0x20))` |
| 2 | `TESObjectREFR` → 0x98, `REFERENCE_RUNTIME_DATA` 0x88 | assert размера + `offsetof(loadedState)` |
| 3 | `Actor` → 0x2B0, шесть смещений из таблицы | asserts в `Actor.h` |
| 4 | `PlayerCharacter` — четыре смещения | asserts |
| 5 | `BSAnimationGraphManager`, `CombatController`, `Inventory3DManager`, `TESObjectCELL` | asserts |
| 6 | Прогон `compare_layouts.py` для профиля 1597 | все дельты должны стать `+0x0` |

Оценка: **3–5 дней** вместо 15–25 из первой версии плана. Основное время уйдёт
не на правки, а на проверку в игре: у форка 247 `static_assert`, и часть
структур появилась после 2021 года — для них сверять не с чем, кроме NG.

### Состояние реализации

| Шаг | Класс | Статус |
|---|---|---|
| 1 | `ExtraDataList` 0x20 → 0x18 (деструктор не виртуальный) | сделано |
| 2 | `TESObjectREFR` 0xA0 → 0x98 (следствие шага 1) | сделано |
| 3 | `Actor` 0x2B8 → 0x2B0, 13 смещений | сделано |
| 4 | `PlayerCharacter` 0xBE8 → 0xBE0, 5 смещений | сделано |
| 5 | `BSAnimationGraphManager` (`pad_ptrs2` 9 → 8) | сделано |
| 6 | `CombatController` | **открыто** |
| 7 | `TESObjectCELL`, `Inventory3DManager` | не требуются: этих классов в клиенте нет |

«Сделано» означает: код собирается по макросам для обоих профилей и содержит
утверждения для обеих раскладок. **Ни одна из этих правок не проверена
компиляцией на Windows и не проверена в игре** — в среде разработки нет MSVC и
Skyrim. Профиль `1600` (по умолчанию) при этом остаётся байт-в-байт прежним:
все правки либо под `#if`, либо параметризованы `TP_LAYOUT(se, ae)`, где `ae` —
старое значение.

`CombatController` оставлен открытым сознательно. По NG блок runtime data
сдвинут на 0x68 → 0x70, но в классе форка в этом месте нет явного паддинга,
поэтому «сдвинуть на 8» нельзя, не поняв, какое именно поле добавлено в
1.6.629. Здесь нужен разбор в игре (или сверка с IDA), чтобы не выдумывать
смещение.

## 6. Что обязательно проверить в игре

1. `Actor::flags1` (0xE0) читается/пишется без сдвига: смерть, воскрешение,
   `SetEssential`.
2. `Actor::actorState` (0xB8) — анимации и боевые состояния.
3. `ActorValueOwner` (0xB0) — здоровье/магия/стамина в UI и в уроне.
4. `PlayerCharacter` runtime data — камера, инвентарь, цели.
5. `TESObjectCELL` runtime data — переходы между ячейками.
6. `CombatController` — агрессия NPC и выбор цели.
7. `Inventory3DManager` — предпросмотр предметов (менее критично).
8. `BSAnimationGraphManager` — проигрывание анимаций.

Пункты 1–3 и 8 — блокирующие: без них клиент нельзя считать работающим.

## 7. Источники

* CommonLibSSE-NG: `include/RE/**` (`STATIC_ASSERT_SIZE`,
  `RUNTIME_DATA_ACCESSOR_VERSIONED`, `RUNTIME_CAST_ACCESSOR_VERSIONED`);
* дерево TiltedEvolution до `a53644e0` (ноябрь 2021) — раскладки 1.5.97,
  проверенные тогдашними запусками;
* `tools/port1597/compare_layouts.py` — сверка утверждений двух деревьев;
* `docs/phase1/layout_diff.csv` — машинный результат сверки.
