# Опыт в мультиплеере и пайплайн RFAB

## 1. Как RFAB начисляет опыт (источник истины)

Полный исходник найден в сборке: `MO2/mods/RFAB/scripts/source/RFAB_XP_Handler.psc`
(в репозитории `drake1ch/RFAB`). Ключевое:

```papyrus
Function ModXP(int aiXP)          ; единственная точка начисления
    PlayerXP.Mod(aiXP)            ; GlobalVariable (float), «полный» счётчик RFAB
    VanilaXPGain(aiXP)
EndFunction

Function VanilaXPGain(int aiXPAmount)
    float _PlayerXP = Game.GetPlayerExperience() + aiXPAmount
    Game.SetPlayerExperience(_PlayerXP)
    if _PlayerXP >= Game.GetExperienceForLevel(Player.GetLevel()) && ShowLevelUp
        ShowLevelUp = false
        ShowLevelUp()             ; анимация полосы уровня
    endif
EndFunction
```

Все события (`OnKill`, `OnBookRead`, `OnQuestComplete`, `CustomReward`) идут
через `ModXP`. Множитель `MultiplierXP` применяется до него, в `CalculateXP`.

Следствия для мультиплеера:

* «начислить опыт» = изменить **два** места: глобал `PlayerXP` и ванильный
  `Game.GetPlayerExperience()`. Одно без другого ломает либо счётчик RFAB,
  либо полосу уровня;
* опыт — целое (`int aiXP`), хранится как float-глобал;
* инициатор события уже получил опыт локально через свой `ModXP`.

## 2. Что делает мод

### Клиент

`Code/client/Services/Generic/CharacterService.cpp`:

* раз в 1000 мс читает глобал `PlayerXP` (`RfabXp::Read()`); если он вырос —
  отправляет `SyncRfabExperienceRequest{Experience = delta, Sequence = ++n}`;
* при получении `NotifySyncRfabExperience` применяет награду
  (`RfabXp::Award(delta)`), затем обновляет `m_lastRfabExperience`, чтобы
  «чужая» награда не ушла обратно на сервер как своя;
* при дисконнекте `Sequence` сбрасывается в 0 (новая сессия).

`Code/client/Services/RfabXp.h/.cpp` — награда на принимающей стороне:
повторяет тело `ModXP` один-в-один (глобал += XP, `SetPlayerExperience(+XP)`),
плюс проверка порога уровня по `Game.GetExperienceForLevel`.

> Почему не прямой вызов `ModXP`: это Papyrus-**функция**, а не нативное
> событие. Чтобы её вызвать, нужно собрать `BSScript::Stack` и вызвать
> `IFunction::Call` — в репозитории такого пути нет, проверить его без сборки
> невозможно, а ошибка в раскладке стека = CTD. Поэтому выбран вариант
> «воспроизвести тело ModXP»: интерфейс `Award(int32_t)` совпадает с
> `ModXP(int)`, и если появится проверенный нативный диспатч, меняется только
> тело функции. Это помечено в отчёте как отклонение от буквы требования при
> сохранении его смысла (обе записи обновляются так же, как это делает RFAB).

### Сервер

`Code/server/Services/XpShareService.cpp`:

| Слой | Что делает | Зачем |
| --- | --- | --- |
| Санитайз | `SanitiseAmount` ≤ 100 000, `min(Experience, 1'000'000)` на входе | клиент не может влить миллион XP |
| Sequence | монотонный номер на игрока; 0 = новая сессия; повторы/out-of-order отбрасываются | защита от дублей пакетов и реплея |
| Окно суммы | одинаковая сумма от разных игроков в пределах 5000 мс рассылается один раз | одно и то же событие (квест/убийство) приходит от всех клиентов |
| Рассылка | `SendToPlayers(notify, pSender)` — всем, кроме автора | опыт равный для всех игроков сервера; автор уже получил его локально |
| Флаг | `Gameplay:bXpShareWholeServer` (по умолчанию `true`), `false` = только партия | откат к старому поведению без пересборки |

Флаг `Gameplay:bEnableRfabXpSync` (по умолчанию `true`) выключает слой целиком.

## 3. Известные ограничения

1. Дедуп по сумме: два **разных** события с одинаковым количеством XP внутри
   5 с схлопнутся в одно. Отключается `Gameplay:uXpShareDedupWindowMs = 0`
   (тогда риск двойного начисления от синхронных квестов).
2. `CalculateXP` (множитель `MultiplierXP`) применяется на клиенте-инициаторе,
   поэтому множитель должен быть одинаковым у всех — он и так берётся из
   `RFAB_XP_Settings.json` сборки.
3. Потолок тотала — 10 000 000 (`kMaxTotalXp`): float-глобал теряет точность
   выше 2^24.
4. Уровневая анимация RFAB не воспроизводится; вместо неё HUD-строка
   `Level up`. Ванильный уровень при этом растёт штатно
   (`SetPlayerExperience`).
5. Опыт, полученный в одиночной игре, никуда не отправляется: клиент шлёт
   дельты только при активном соединении.

## 4. Ручная проверка

**Требует проверки в игре.**

1. Два клиента на сервере, один убивает NPC → у обоих `PlayerXP` вырос на
   одинаковую величину, полоса уровня у обоих сдвинулась.
2. Убийство, за которое RFAB даёт < 5 XP (например, крыса) → награда не
   теряется и не дублируется.
3. Квест, который завершают оба игрока одновременно → награда начислена один
   раз (окно дедупа), в логе сервера `suppressed duplicate amount`.
4. Убийство, пока второй игрок в другой ячейке → опыт приходит и ему.
5. Дисконнект/реконнект клиента → счётчик продолжает расти, реплеи не
   начисляются (`rejected replayed report`).
6. `Gameplay:uXpShareDedupWindowMs=0` → каждое событие начисляется каждому
   отдельно, дубли возможны (ожидаемо).
